### Формирование User Story

#### 1. Формат User Story
```
Как <роль>
Я хочу <действие/возможность>
Чтобы <ценность/результат>
```

#### 2. Проверка по INVEST
- **Independent** — история не зависит от других историй в реализации
- **Negotiable** — детали обсуждаемы, это не жёсткая спецификация
- **Valuable** — приносит ценность пользователю или бизнесу
- **Estimable** — можно оценить трудоёмкость
- **Small** — реализуется в рамках одного спринта
- **Testable** — есть проверяемые критерии приемки

#### 3. Acceptance Criteria в формате Gherkin
```gherkin
Feature: <название фичи>

Scenario: <название сценария>
  Given <начальные условия>
  When <действие пользователя>
  Then <ожидаемый результат>

Scenario: <альтернативный/ошибочный сценарий>
  Given <условие>
  When <действие>
  Then <результат ошибки/исключения>
```

#### 4. Обязательные элементы User Story
1. Уникальный идентификатор: US-XXX
2. Формулировка "Как... Я хочу... Чтобы..."
3. Минимум 1 основной и 1 альтернативный/ошибочный сценарий в Gherkin
4. Приоритет (MoSCoW или числовой RICE score)
5. Оценка (Story Points, T-shirt size)
6. Бизнес-ценность (1-2 предложения: почему это важно)
7. Зависимости от других историй (если есть)

#### 5. Пример
```
US-014: Быстрая оплата сохранённой картой

Как зарегистрированный пользователь
Я хочу оплатить заказ ранее сохранённой картой в один клик
Чтобы не вводить данные карты повторно при каждой покупке

Приоритет: High (RICE: 8.4)
Оценка: 5 story points
Ценность: Снижение отказов на этапе оплаты (текущий conversion drop 23%)

Feature: Быстрая оплата сохраненной картой

Scenario: Успешная оплата сохраненной картой
  Given пользователь авторизован и имеет сохраненную карту
  When пользователь нажимает "Оплатить сохраненной картой"
  Then заказ оплачивается без повторного ввода данных карты
  And пользователь видит подтверждение оплаты

Scenario: Карта просрочена
  Given у пользователя сохранена карта с истекшим сроком действия
  When пользователь пытается оплатить этой картой
  Then система показывает сообщение "Срок действия карты истёк"
  And предлагает добавить новую карту
```

#### 6. Чек-лист качества
- [ ] Формулировка "Как/Я хочу/Чтобы" присутствует и конкретна
- [ ] История соответствует всем 6 критериям INVEST
- [ ] Минимум 2 сценария в Gherkin (успешный + альтернативный/ошибка)
- [ ] Указан приоритет и оценка
- [ ] Указана бизнес-ценность
- [ ] Нет технических деталей реализации (это задача системного аналитика)
