### Бизнес-кейс инициативы

#### 1. Обязательная структура
1. **Проблема/возможность** — что не так сейчас или какая возможность упускается
2. **Предлагаемое решение** — краткое описание инициативы
3. **Целевая аудитория и охват**
4. **Финансовая модель** — затраты, выгоды, ROI, срок окупаемости
5. **Риски и допущения**
6. **Альтернативы** — что рассматривалось и почему отклонено
7. **Рекомендация** — go/no-go с аргументацией

#### 2. Финансовая модель
```
ROI = (Выгода - Затраты) / Затраты × 100%

TCO (Total Cost of Ownership) = 
  Затраты на разработку 
  + Затраты на инфраструктуру (год)
  + Затраты на поддержку (год)
  + Затраты на обучение персонала

Payback Period = Затраты / (Годовая выгода / 12) [месяцев]
```

#### 3. Оценка выгоды
- **Прямая выгода**: рост выручки, снижение затрат, снижение потерь (например, фрод)
- **Косвенная выгода**: NPS/CSAT рост, снижение оттока, ускорение time-to-market
- Для банковской/финтех-специфики: снижение операционных рисков, соответствие требованиям ЦБ РФ, снижение стоимости фрода

#### 4. Шаблон бизнес-кейса
```markdown
# Бизнес-кейс: {название инициативы}

## Проблема
{описание проблемы с цифрами: текущие потери, недополученная выручка}

## Решение
{краткое описание, 3-5 предложений}

## Финансовая модель
| Показатель | Значение |
|---|---|
| Затраты на разработку | ... |
| Затраты на поддержку (год) | ... |
| Ожидаемая выгода (год) | ... |
| ROI (1 год) | ... % |
| Payback Period | ... мес. |

## Риски
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|

## Альтернативы
{рассмотренные варианты и причина отклонения}

## Рекомендация
{Go / No-Go / Требует дополнительных данных}
```

#### 5. Чек-лист качества
- [ ] Проблема количественно обоснована (не просто "неудобно")
- [ ] Финансовая модель содержит реальные или явно обозначенные оценочные цифры
- [ ] ROI и Payback Period рассчитаны по формулам, а не оценены "на глаз"
- [ ] Указаны минимум 3 риска с митигацией
- [ ] Рассмотрена хотя бы 1 альтернатива
- [ ] Дана явная рекомендация
